# What the care server and the care worker need at run time: the input of requirements-api.lock,
# which the production API image (deploy/Dockerfile.api) installs with
#
#   pip install --no-deps --require-hashes -r requirements-api.lock
#   pip install --no-deps --require-hashes -r requirements-nodeps.txt
#
# It is a subset of requirements.txt, at requirements.txt's versions. The full server's model
# stack (torch, sentence-transformers, speechbrain, playwright and the rest) is not here: the
# care server does not load it. Nothing that only the tests need is here either (pytest,
# pytest-asyncio, moto and what they pull in: Werkzeug, responses, xmltodict, iniconfig,
# pluggy); those stay in requirements-test.txt, which CI installs in its own jobs and the
# image's `test` stage adds on top of the runtime stage.
#
# requirements-api.lock is DERIVED, not resolved afresh: every package in it carries the
# version and the hashes requirements.lock carries for it. Regenerate after changing this file
# or requirements.lock:
#
#   python scripts/api_image_lock.py --write      # needs PyPI (uv resolves the subset)
#   python scripts/api_image_lock.py --check      # offline; tests/architecture/test_api_image_lock.py
#
# faster-whisper is not here: it goes in with --no-deps from requirements-nodeps.txt (no PyAV,
# docs/security/LICENCES.md). Its other dependencies are here.
